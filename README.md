# inno-l2-editor

给 [InnoSpark](https://github.com/hhyqhh/inno-agent) 的 **L2 Wiki 知识库**补一套更好的写入体验：
**AI 负责整理，用户负责决定。**

---

## 这个项目解决什么问题

InnoSpark 的 L2 是一套 Obsidian 范式的知识库——`wiki/` 下的 Markdown 文件本身就是真源，
用 `[[wikilinks]]` 交叉引用，tag 写在 frontmatter 里。它的潜力没有被充分用起来，
往里写东西目前有两条路，两条都不好走：

**一、让主代理用自然语言写。** 改一处要绕好几轮对话说清楚，看不到改动前后的差异；
更要紧的是它**挤占主代理的上下文**——"要不要归档""建哪几页""改哪一处"这些决策和交互，
占的是本该用于教学任务的那部分注意力。

**二、自己手改 md。** 面对的是没渲染的源码，还得懂 Markdown、自己维护条目之间的关联。
门槛高、也不好看。

这个项目补的就是中间那一层：**把渲染层和结构化编辑做出来，把 AI 的活挪到独立子代理里。**

## 它做了什么

**结构化编辑，不用碰 YAML。** tag 和「相关知识」在右侧面板里点着改，
加关联会自动双向写入对端页面。md 文件**始终可以手改**——系统只托管
frontmatter 的 `tags` 和正文里 `## 相关知识` 这一段，其余内容读写全程原样保留，
一个字节都不动。你在 Obsidian 里改完再回来，以文件为准。

**AI 润色跑在独立会话里。** 编辑态选中一段文字唤起子代理。那个会话
**工具数为 0**——它物理上写不了任何文件，只能提建议，采用之前正文一个字都不会变。
它也不经过主对话，所以不占主代理的上下文。

**从资料生成新页，每条都要能对上原文。** 传一份资料（或把 AI 的几轮回答粘进来），
它会被**冻结**：内容算 hash 存下来，之后任何改动都能被发现。子代理据此产出草稿，
每条都附一句原文引文；服务端逐条核对引文是不是冻结来源的**精确子串**，
核不上的当场拦下、标红显示——**不会被悄悄删掉**，好让你看见模型说了什么、
以及为什么不能信。

这条最后的机制是为了回答一个很实际的问题：**"这条到底是不是它编的？"**

## 设计上的几个取舍

**独立进程，只赌公开接口。** 独立端口、视图层另写一套，而不是复用 InnoSpark 的组件。
代价是有重复，收益是它内部结构怎么改这边都不用跟着改——耦合面只有两处：
**来源摄入**与**读写 L2**。

**模型没有正式写权限。** 不是靠约定，是靠结构：子代理零工具，所有落盘都要经过
用户在界面上点一下，服务端在写盘那一侧还会把引文重新核对一遍
（界面可以撒谎，服务端不信）。

**做不到的如实标注。** 未解析的链接显示为橙色幻影节点而不是悄悄丢掉；
编辑沙盒样例时左上角会标明「非真实库」；模型没配好就说没配好。
这些不是防御性文案，是这个项目的验收标准之一。

## 前置条件

- **Node.js >= 22.19.0**（`node -v` 检查）
- 一个装好的 InnoSpark（可选，但强烈建议——不装的话只能编辑自带样例）

## 安装

```bash
git clone https://github.com/netzach-star/inno-l2-editor.git
cd inno-l2-editor
npm install
```

`npm install` 只装一个可选依赖 `@earendil-works/pi-coding-agent`，它**只服务于 AI 功能**。
不装也能跑，只是润色和「从资料生成」会如实报「未配置」，其余功能照常。

## 启动

```bash
INNO_AGENT_DIR=/path/to/inno-agent node server.mjs
```

打开 http://localhost:4321 。

`INNO_AGENT_DIR` 指向 InnoSpark 的**安装目录**（就是有 `restart-dev.sh` 的那一层）。
指对了，两件事同时成立：

| | 从哪来 |
|---|---|
| 编辑的知识库 | `$INNO_AGENT_DIR/runtime/data/l2/wiki` —— InnoSpark 的真实 L2 |
| 模型配置 | `$INNO_AGENT_DIR/runtime/config/config.json` —— 和主代理**同一份** |

**为什么强调「同一份」**：两个程序各读各的配置，会出现主代理报 401、
而这边显示「已配置」的诡异状况。踩过一次，所以现在只认一个来源。

不设 `INNO_AGENT_DIR` 也能启动，此时编辑的是仓库自带的 `sample/wiki`（三页示例），
左上角会用橙色标明「非真实库」——不会让你误以为在改真东西。

### 其他环境变量

| 变量 | 作用 |
|---|---|
| `INNO_AGENT_DIR` | InnoSpark 安装目录（推荐，一个顶下面三个） |
| `INNO_WIKI_DIR` | 单独指定 wiki 目录 |
| `INNO_MODEL_CONFIG` | 单独指定模型配置文件 |
| `INNO_API_KEY` | 覆盖配置里的 key，不落任何文件 |
| `INNO_SOURCES_DIR` | 冻结来源的存放位置，默认 `./data/sources` |

没装 InnoSpark 又想用 AI 功能：

```bash
cp model.config.example.json model.config.json   # 已 gitignore
# 填进 apiKey，然后 node server.mjs
```

## 怎么用

### 编辑已有页面

左侧选页 → 右侧改 tag 和「相关知识」→ 「保存并写回 md」。

- **md 文件始终可手改**。系统只托管 frontmatter 的 `tags` 和正文里 `## 相关知识` 这一段，
  其余内容读写全程原样保留，一个字节都不动。你在 Obsidian 里改完再回来，这边以文件为准。
- 加关联会**双向写入**：对端页面也会出现这一条。
- 正文里手写的 `[[wikilink]]` 同样算正式关联，面板中以虚线框回显；
  要删请到正文里删——系统不替你改写自己的句子。

### 让 AI 润色

编辑态选中一段 → 下方按钮或 `⌘K` → 看建议 → 「采用」或「放弃」。

采用之前正文一个字都不会变。子代理跑在独立会话、**工具数为 0**，它写不了任何文件，
只能提建议。

### 从资料生成新页

左上「＋ 从资料生成新页」：

1. 传一个 `.md`/`.txt`，或把 AI 的几轮回答粘进来攒成一份
2. 资料被**冻结**（内容寻址 + hash），之后任何改动都能被发现
3. 子代理读冻结来源，产出草稿，每条都附一句原文引文
4. 服务端逐条核对引文是不是冻结来源的**精确子串**，核不上的标红拦下
5. 你勾选要留的，落盘成新的 concept 页

核不上的条目**不会被悄悄删掉**——它们留在界面上，好让你看见模型说了什么、
以及为什么不能信。

## 核验

三个脚本，都不需要 API key：

```bash
node check-citation.mjs    # 25 项：引文校验与来源冻结
node check-isolation.mjs   #  6 项：子代理隔离
node check-pipeline.mjs    # 27 项：写盘边界（需先启动 server.mjs）
```

它们钉住的是这几条不变量：

- 模型**没有**正式写权限（子代理零工具，落盘一律经用户确认）
- 引文必须是冻结来源的精确子串，**编造的当场拦下**
- 界面可以撒谎，服务端不信——写盘那一侧会重新逐条核对
- 冻结对账在引文校验**之前**：文件被改过就一律拒绝

## 目录

| 文件 | 职责 |
|---|---|
| `server.mjs` | HTTP、md 读写、链接解析、图谱构建 |
| `index.html` | 全部前端（无框架、无构建） |
| `polish-agent.mjs` | 子代理：隔离会话、润色、从来源编译 |
| `citation.mjs` | 引文校验 |
| `source-store.mjs` | 来源冻结，内容寻址 + hash 对账 |
| `check-*.mjs` | 核验脚本 |
| `sample/wiki/` | 三页示例，没接 InnoSpark 时用（内容为自撰常识，不取自任何教材） |
| `data/sources/` | 冻结来源，运行时生成，不进仓库 |

## 和 InnoSpark 的关系

刻意保持独立：独立进程、独立端口，视图层另写一套而不是复用它的组件。
代价是有重复，收益是 InnoSpark 内部结构变了这边也不用跟着改——
耦合面只有两处，**来源摄入**与**读写 L2**。

上游行为一律以其源码为准。链接解析与图谱构建口径移植自
`apps/inno-agent/src/memory/l2/wiki-links.ts` 与 `wiki-graph.ts`，
引文校验的规范化逻辑移植自知识编译器的 `canonical.ts`，两边不各写一套。

> 一处有意的偏离：引文规范化多了「去掉两个中日韩字符之间的空白」一步。
> 上游那套为空格分词语言设计，中文在句子中间换行会多出一个空格导致**合法引用**匹配失败。
> 该步骤只动空白、不删实体字符，跨段拼接照样拦得住（`check-citation.mjs` 有断言）。

## 已知边界

不做：Git 式三方合并、多用户实时协作、任意 Markdown 全量反向解析、
语义关系类型与方向、学习路径推理、图谱画布编辑、PDF 直接解析（当前支持 `.md` / `.txt`）。

数学公式当前不渲染 KaTeX——InnoSpark 自带的笔记本视图渲染，这边还没补。
