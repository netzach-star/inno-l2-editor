## 一句话

把 KaTeX 接进编辑器，**约 70 行代码 + 一个可选依赖**，不引入构建步骤。

---

## 0. 先说清楚这件事为什么值得做（口径不能含糊）

**它不解决当下的痛。** 实测：现有四个知识库共 63 页，**正文含公式的是 0 页**。
上游 `summarizeContent` 与我们的 `compileConcept` 都会把公式改写成中文散文，
所以 LaTeX 只活在原文那一侧（`raw/` `extracted/` 与引文），进不到任何 wiki 页面上。
这是 `执行决议.md` D-16 的结论，**至今仍然成立**。

**它的价值是解除封锁。**

> 页面上没有公式，是**提示词决定的**，不是用户偏好。
> 数学内容被散文化本身是一次保真度损失。
> 将来想让 `compileConcept` 保留公式是很合理的诉求——
> 但**得先有渲染，才敢改提示词**，否则页面立刻变成一堆 `\frac{1}{n^2}`。

所以这 70 行买的是「那个提示词决定从此可逆」，不是「用户现在看得到公式」。
**对外描述时要这么说**，别说成"修好了一个渲染 bug"（红线 3）。

## 1. 上游的三样东西，三种结论

问题的起点是「为什么不直接照搬上游的」。答案是：**能搬，但其中一样搬过来反而是错的。**

| 上游的东西 | 结论 | 为什么 |
|---|---|---|
| `<markdown-artifact>` 组件 | **搬不了** | pi-web-ui 的 ESM bundle，依赖图大到上游自己得在 vite 里 stub 掉 `@lmstudio/sdk`。我们是纯 `<script>`、没有打包器，这条路封死 |
| `normalizeMarkdownMath`（138 行） | **能搬，但不该搬** | 见下 |
| KaTeX 本身 + 官方 auto-render | **这才是该搬的** | dist 本来就是为 `<script src>` 设计的，不需要任何构建工具 |

### 那 138 行为什么不该搬

它**全部**在解决一个问题：上游的渲染器在 KaTeX 之前就把 `<` 转义成了 `&lt;`，
于是要手工把 `&lt;`→`\lt`、`&le;`→`\le` 一路转回 TeX 命令。

但那是**字符串管线**的毛病。我们走 **DOM 后处理**——先 `innerHTML`，再让 KaTeX 扫文本节点——
`&lt;` 在进 DOM 那一刻就被浏览器解码回真正的 `<` 了。**这个坑我们天然不踩。**

> 照搬等于抄了一副治别人病的药。
> 这是「复用上游」这条准则的一个边界：**复用的是能力，不是别人的补丁。**

## 2. 两个白捡的便宜

**① 我们那 44 行的简陋渲染器，在这件事上是优势。**

`renderMd` 的 `inline()` 只做三件事：`[[wikilink]]`、`` `code` ``、`**bold**`。
**它不处理 `_斜体_`，也不处理单个 `*`。**
而这两个恰恰是 markdown 吃掉 TeX 的主要途径——`$a_1$` 在全功能渲染器里会被下划线规则拆掉，
得专门加插件保护。我们天然没这个问题。

**② auto-render 的默认定界符正好对上取样结论。**

它的默认列表本来就**不含单个 `$`**（只有 `$$`、`\(`、`\[`、`\begin{equation|align|alignat|gather|CD}`）。
而 §17 的取样分布是：

| 记法 | 次数 | 出现在几条回答 |
|---|---|---|
| `\(…\)` | 208 | 9 |
| `\[…\]` | 39 | 7 |
| `$…$` | 24 | **1** |
| `$$…$$` | 5 | 2 |

**多数项目接 markdown-math 要改配置才不漏九成公式，我们用默认配置就是对的。**

顺带：不认单个 `$` 还避免了中文正文里 `$100`、`$200` 被当成公式吃掉——已有断言。

## 3. 改了什么

### 3.1 `server.mjs`：静态资源路由（约 25 行）

这个服务原先**只伺服 `index.html` 一个文件**。新增 `/vendor/katex/*` → `node_modules/katex/dist/*`。

- **为什么伺服本地而不是 CDN**：编辑器改的是本地知识库，不该因为断网就渲染不出公式；
- **防路径穿越**：白名单扩展名 + 拒绝 `..` + `relative(base, abs)` 二次校验。
  已测：`%2e%2e%2f` 与 `..%2f` 均返回 400，`fonts/../../../` 返回 404；
- **没装 katex 时如实 404**，不伪造空文件让前端以为拿到了。

### 3.2 `index.html`：挂载 + 渲染入口（约 30 行）

`<head>` 里三行 `<link>` / `<script defer>`，外加一个 `renderMath(el)`：

```js
function renderMath(el) {
  if (typeof renderMathInElement !== "function") return;   // 可选依赖没装，安静跳过
  try {
    renderMathInElement(el, {
      delimiters: MATH_DELIMS,
      ignoredTags: ["script", "noscript", "style", "textarea", "pre", "code"],
      throwOnError: false,
    });
  } catch (err) {
    console.warn("KaTeX 渲染失败，公式将原样显示", err);   // 不把整页带崩
  }
}
```

`ignoredTags` 里的 `code` 让行内代码和代码块自动豁免——
上游那个手写的 `normalizeOutsideFencedCode` 围栏跳过逻辑，**我们靠 DOM 结构白拿**。

两个挂载点（正文渲染 `index.html` 的 `drawDoc`、教程弹窗的示例渲染）各调一次。

### 3.3 `index.html`：跨行行间公式的预处理（约 15 行）

**auto-render 唯一接不住的情况。**

`renderMd` 按 `\n` 切行、每行包一个 `<p>`，所以一个跨三行的 `\[ … \]` 会被切进三个元素，
而 auto-render **不跨元素合并**——它只在单个文本节点里找配对的定界符。
结果是三行都渲染不出来，还各自露着半个定界符。

做法：切行之前先扫一遍，把**跨行的** `\[…\]` 与 `$$…$$` 整块换成占位符，
最后作为**单个** `<div class="mathblock">` 放回去。
这是"先切数学、再跑 markdown"那个正确顺序的最小实现。

单行的不动——它本来就在一个 `<p>` 里，auto-render 接得住。

> **一个自己的断言抓出来的 bug**：占位符用 NUL 包裹，
> 如果正文里**恰好**出现形如占位符的文本，最后会被替换成 `undefined`。
> 两道防线：进门先剥掉正文里的 NUL（它在 Markdown 里没有合法用途）；
> 替换时越界就原样留着。剥 NUL 只影响**显示**——`renderMd` 的产物从不写回文件。

### 3.4 `package.json`：katex 记进 `optionalDependencies`

沿用 `polish-agent` 那条既有纪律：**不装也能跑**。
没装时 `/vendor/katex/*` 返回 404 → 前端拿不到 `renderMathInElement` → 跳过渲染 →
公式原样显示（= 装之前的行为），**其余功能一律不受影响**。

## 6. 没做什么

- **不改 `compileConcept` 的提示词。** 让页面保留公式是另一个决定，
  影响引文定位的口径（引文要一字不差照抄，公式进正文后 quote 的匹配面会变），
  要单独评估。**这次只是把渲染准备好，让那个决定变得可做。**
- **不碰引文对照区的显示。** 引文要显示**原样字节**——你要核对模型有没有编，
  就得看到源里到底写了什么，渲染反而妨碍核对。这条 D-16 的结论不变。
- **不补表格 / 代码块 / 图片。** 那些是 §15 待决 7，人类 2026-08-08 已裁定挂起。
  本次只动公式这一样，`renderMd` 的块级分支一条没加。

## 7. 已知限制

1. **公式在编辑态不渲染。** 点「编辑正文」进 textarea 后看到的是原始 TeX。
   这是有意的——编辑时要改的就是源码。
2. **`\begin{...}` 环境走 auto-render 的默认支持**（`equation` / `align` / `alignat` /
   `gather` / `CD`），别的环境不认。取样里这类只有 4 次 / 3 条，暂不扩。
3. **首次打开带公式的页会有一次字体请求的闪动**（FOUT）。
   345 KB 的载荷里字体是按需的，本地伺服延迟极低，实测感知不明显，未做处理。
